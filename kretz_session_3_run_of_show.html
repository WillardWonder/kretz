The approval loop that never ends

Tell the story (anonymized), then have the room define "done" for one real Kretz work product using the checklist tool. The point lands when they see APPROVED appear while suggestions are still listed.

Principle 2

The story

"An organization I've worked with replaced a checklist with AI. One AI tool wrote the content, tuned to pass the checklist. Another AI tool reviewed it, and was also asked to suggest improvements. It always found one. Work that passed every item went back for revision anyway, and approvals stopped."

The teaching point. An AI reviewer can always find something to improve. Without a stop rule and an owner who decides "good enough," review never ends. Once the builder tool is tuned to pass the checklist, passing it stops proving quality, so the owner has to review the checklist itself against real outcomes.

Exercise — on the participant page, Checklist section
1. Click "Load: outgoing landowner letter." 2. Name the checklist owner. Watch the status change from "No checklist owner." 3. Mark every item Pass. Watch it say APPROVED. 4. Add two suggestions. It still says APPROVED. 5. Mark one item Fail. Now it is blocked, and only that item needs fixing. 6. Type "Make the letter better" as a new item and read the warning.
Stop-rule review prompt — for ChatGPT
Review the work below against this checklist only: [paste checklist]. For each item, answer PASS or FAIL with one sentence of evidence. If every item passes, say "APPROVED" and stop. Put any other ideas under "Optional suggestions — not required for approval." Do not use them to fail an item. Work: [paste or upload]

Policy → procedure → workflow

Build one complete chain live, for the policy that matters most right now: AI-assisted valuations. Start in ChatGPT, then load the Kretz example in the builder and edit it until the room agrees. The deliverable is a procedure with a named sign-off role.

Principle 1
Step 1 — the policy, in one sentence
AI-assisted land, timber and hunting-property valuations are decision support. No AI-produced figure reaches an offer, letter or report without named sign-off.
Step 2 — ChatGPT turns it into steps
Here is a company policy: AI-assisted land, timber and hunting-property valuations are decision support. No AI-produced figure reaches an offer, letter or report without named sign-off. Turn it into: 1. A procedure: numbered steps, each with a role responsible and the trigger or deadline. 2. A workflow: the tools and hand-offs the steps run through, marking every sign-off point. 3. Gaps: any step with no owner, any decision with no sign-off, anything the policy requires that no step covers. Do not add requirements that are not in the policy. List suggested additions separately.

What to watch for

ChatGPT will propose steps that sound right but have "the appropriate person" as the owner. Push for an actual role. Then move to the builder ("Load Kretz valuation example") and let them change roles, triggers and stages. The builder's warnings do the arguing for you: no owner, no trigger, no sign-off point.

Capture: the sign-off role for valuations, and the person who holds it.

Live review: AI valuation tools

Wyatt demonstrates his valuation tool on one parcel (10 min). The room runs the valuation checklist on that output (15 min). Then Parcel Scout on the same parcel as the comparison (10 min). This is the block Kretz asked for; protect its time.

Tool review
On the participant page
Checklist section → "Load: AI valuation tool review" → name the checklist owner → mark each item as a group, with one line of evidence.

The question for every number

Point at one figure on screen and ask: where did this come from, and could the AI have made it up? If the answer is "the model knows," that is a fail on item 1, not a judgment on Wyatt. The fix is usually structural: give the tool the data, or do the math in a spreadsheet or code, and let the AI explain rather than invent.

Parcel Scout's own story. Its first version asked an AI model for tax values and timber estimates from a parcel ID, county and owner name only. The model had nothing to look up. The rebuild fetches every number from public records in code and rejects any AI-written number that is not in the record. Use it to show what "pass" looks like on items 1, 2, 3 and 6, and to show that it still fails item 7 until Kretz names a sign-off owner.

Fallback if the valuation tool is unavailable
Without browsing the web, estimate the current timber value and total market value of a 40-acre wooded parcel in Langlade County, Wisconsin. Give specific dollar figures.

Fallback teaching point

Run the checklist on ChatGPT's answer. It will usually produce confident dollar figures with no parcel data, no stand data and no stumpage source. Items 1, 2, 3 and 6 fail. That is exactly the failure the valuation procedure exists to catch.

Fill in a card for every AI tool Kretz uses today: Wyatt's valuation tool, the Kretz DNA Assistant, the AI Decision Guide, Parcel Scout. A card is not cleared until a sign-off owner is named or the builder accepts ownership. Download each card as a file and save it to the register; at the end, export the register file and CSV from the AI Tool Register page.

Principle 3
Draft a card with ChatGPT first, if useful
Draft a one-page AI Tool Card for this tool: [describe the tool]. Fields: tool name, what it does in one sentence, who uses it, builder, sign-off owner, decisions it supports, data it uses with sources, data it must never receive, checklist it must pass, what happens when it is wrong, next review date. Where you do not know a field, write "NEEDS OWNER INPUT". Do not guess names, data sources or dates.

What to watch for

Silence when you ask "who signs off?" is the finding. Do not fill it in for them. If nobody takes it, the card says the builder owns the outcome, and the builder should hear that out loud.

01:3018 min

Build your own register

The control-and-compliance exercise. The room decides where Kretz's AI tool register will live, builds a first version with ChatGPT, seeds it with today's Tool Cards, and judges it against the nine register requirements. The AI Tool Register page and the reference workbook are examples, not the answer.

Control
Decide first (2 minutes)
Where will the register live so that the right people can find it, edit it, and it is backed up? - A spreadsheet in a shared folder (Excel / OneDrive / SharePoint) - A SharePoint or Teams list - A small tool someone owns Who owns the register itself?
Build (10 minutes) — prompts are on the participant page
Participant page → "Build your own register" → copy the Excel, SharePoint list, or small-tool prompt. Seed data: AI Tool Register page → Export CSV (the Tool Cards made in the last block).
Judge it (5 minutes)
Participant page → Checklist → "Load: register requirements" → name the register owner → mark each of the nine items Pass or Fail. Pass means done.

What to watch for

ChatGPT will often type "Cleared" as text instead of writing a formula. That fails requirement 3: point it out and ask for the formula. SharePoint calculated columns cannot use today's date, so the overdue check belongs in a filtered view; let ChatGPT say so, and check that it does. Requirements 7 and 8 (edit control, backup) are settings where the file or list is stored, not features of the file itself.

Fallback: open the reference register workbook, paste the exported CSV into the Register sheet (columns A–N), and run the requirements on the workbook's own Requirements sheet. Capture: where the register lives and who owns it.
