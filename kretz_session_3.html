Three operating principles.

Kretz already has the rules: Sign-Off, No-Fault Reporting, Kretz DNA. These principles make the rules run day to day.

📜

1. Every policy needs a procedure and a workflow.

Policy is the rule and why it exists. Procedure is the steps: who, what, when. Workflow is the real path through people and tools, including where sign-off happens.

A policy without a procedure is a poster on the wall.

Open the policy builder
✅

2. The checklist is the final judgment.

Every item is pass or fail. When all items pass, the work is done. Review tools check only what is on the list. The checklist's owner must be the right person, and only the owner changes the list, on a schedule, based on real outcomes.

"Good enough" is a decision someone makes, not a failure.

Open the checklist
🖊️

3. The builder owns the outcome.

Whoever builds an AI tool is responsible for what it produces, unless a different sign-off owner is named before the tool goes live. Every tool gets a one-page AI Tool Card. No card, no routine use.

If nobody is named, the builder owns it.

The approval loop that never ends.

A pattern from another organization, worth avoiding before it starts here.

What happened. A team replaced a human checklist with AI. One AI tool produced the content and was tuned to pass the checklist. A second AI tool reviewed the content against the checklist, but it was also allowed to suggest improvements. It always found one. Work that passed every item went back for another round, and approvals stopped.

Why it happened. Nobody had decided what "done" meant. An AI reviewer can always find something to improve, so a review with no stopping point never stops.
1

2

Reviewers check only the list.

Anything beyond the list goes in "optional suggestions." Suggestions never block approval.

Scope rule
3

The owner reviews the checklist, not the tool.

Once a tool is built to pass a checklist, passing it no longer proves quality. The owner checks the list against real outcomes on a set schedule.

    What Parcel Scout's first version got wrong
    It asked an AI model for tax values and timber estimates using only a parcel ID, a county and an owner name. The model had no data to look anything up. The fix: fetch every number from public records in code, and let AI write only the summary. Any number not in the record is rejected.

    Prompts to keep.
    For ChatGPT or any assistant. Each one enforces a principle instead of relying on memory.
    

    

    📜
    Policy to procedure and workflow
    Prompt
    Here is a company policy: [paste policy].
Turn it into:
1. A procedure: numbered steps, each with a role responsible and the trigger or deadline.
2. A workflow: the tools and hand-offs the steps run through, marking every sign-off point.
3. Gaps: any step with no owner, any decision with no sign-off, anything the policy requires that no step covers.
Do not add requirements that are not in the policy. List suggested additions separately.
    

    ✅
    Make a checklist testable
    Prompt
    Rewrite each checklist item below so it is pass/fail: two reviewers looking at the same work would mark it the same way.
Remove words like "better", "high quality", "appropriate", "improve".
Keep the same number of items and the same intent. Do not add new items.
Checklist: [paste items]
    

    🔍
    Review against a checklist, with a stop rule
    Prompt
    Review the work below against this checklist only: [paste checklist].
For each item, answer PASS or FAIL with one sentence of evidence.
If every item passes, say "APPROVED" and stop.
Put any other ideas under "Optional suggestions — not required for approval." Do not use them to fail an item.
Work: [paste or upload]
    

    🖊️
    Draft an AI Tool Card
    Prompt
    Draft a one-page AI Tool Card for this tool: [describe the tool].
Fields: tool name, what it does in one sentence, who uses it, builder, sign-off owner, decisions it supports, data it uses with sources, data it must never receive, checklist it must pass, what happens when it is wrong, next review date.
Where you do not know a field, write "NEEDS OWNER INPUT". Do not guess names, data sources or dates.
